# Spec — a root's versions are an append-only stream; commit is no longer main-only

**Contract.** A commit writes the root's new version as a new entry in the
root's stream, `roots/<name>/<ts>-<hash>`, write-once (moco
`moco:c08aa5551e04cf03a5f4df25c0f647b02dd78d7eacfb3872cb197affc6b52d2a`), instead of overwriting `roots/<name>`. The
current version is the latest head by listing. Two commits made concurrently
— on two branches, two machines, or a phone and a laptop — leave two heads;
the next commit folds them, its version naming both as parents. A commit is
byte-deterministic, so two writers that saw the same events write the same
object and put-once keeps one. A one-time migration moves each existing
`roots/<name>` into its stream.

**Why.** The single overwritten pointer is why `kinora commit` is main-only and
git-bound: two branches rewriting one file conflict. Added files never
conflict in git, and on an object store need no compare-and-swap, so the same
rule serves a project ledger in git and a store with no git at all.

**Rejected.** Compare-and-swap on the pointer (provider-dependent, no offline
commit). A designated committer (nothing commits while it sleeps). Keeping
main-only commit and syncing roots by a separate rule (two mechanisms).

**Escape hatch.** A stream grown long is checkpointed by moco's stream rule;
`kinora repack` may write that checkpoint.
