# Spec — a store syncs with an object store by putting what is missing

**Contract.** A `.kinora/` store can be mirrored to an **object store**
(S3-compatible: Cloudflare R2, AWS S3, MinIO) under a prefix. The mirror holds
the store's **write-once** files — the content blobs (`store/<ab>/<hash>.<ext>`)
and the staged events (`staged/<ab>/<event-hash>.jsonl`) — under the same
relative paths. Two operations, both additive:

- **push** puts every local write-once file the mirror lacks, with a
  conditional create (put-if-absent): a file already there is never
  overwritten, so two machines pushing at once cannot clobber each other. A
  machine remembers what it sent or fetched through a mirror, so a push with
  nothing new makes no request; a **full push** ignores that memory, for a
  mirror that lost files;
- **pull** fetches every mirrored file the local store lacks and checks it
  before it lands: a blob's bytes must hash to its name, an event must be one
  canonical event line hashing to its name. Anything else is refused.

Only names kinora itself writes sync (`<ab>/<hash>…`, the shard being the
hash's first two digits); its temporary files never do. Blobs sync before the
events that cite them, so an interrupted sync never leaves an event without
its content.

Nothing else syncs: `roots/`, `config.styx`, temporary files and anything
outside those two trees stay local. Because every synced file is named by its
hash, there is nothing to merge; concurrent writers meet as kinora's own forks.

**Chosen.** Mirror-and-sync over a storage abstraction inside kinora. kinora
reads and writes plain files in a hundred places; the write-once trees are the
whole of what a store *is* between commits. Syncing them keeps every reader
unchanged, keeps a local working copy for speed and offline use, and makes
the object store the meeting point no machine has to keep awake. It realizes
the context-store requirement declared in kudo
(`kudo:4909f3e9f6d391d8a20dc8587a1ffc33160eb238d86d1cc55d5b9fb9ce754e76`).

**Rejected.** A storage trait threaded through kinora so every read goes to
the object store (rewrites the crate; every resolve becomes network-bound).
Syncing `roots/` too (roots are rewritten by commit: they would need a merge,
and a mirrored context store never commits). git as the transport (ties
reachability to a host).

**Escape hatch.** A committed ledger that needs its roots mirrored can sync
them as an explicit, separate operation with its own conflict rule; the
write-once sync stays as it is.

**Superseded in direction (24 Oct 2026).** Kura design 1 (kudo decision
`kudo:ec5e5aab31d29fc37c0939f3b494f8451a4149f953853caf88aaefe2f17b3a47`) chose a storage trait after all: moco's streaming
`Place` (`moco:a7089331ac0dff49deb5acc9afce92b2a9d8a9d5022f66af915f3a2332d6f447`), every device working through a local working copy
(`moco:7d189e690068d0f7200fcdbb236afe6ab64b6ad6535c8a8a883c3f825b72c79a`). What this spec rejected — every read going to the
object store — is avoided by the working copy, which keeps reads local and
offline, while a place may hold only part of a store (media). The mirror's
rules carry over as moco's: put-if-absent, a pull checked on arrival,
kinora's own names only, blobs before the events citing them. Its code moves
to moco's `ObjectPlace` (`moco-place-s3`) as a working copy's remote;
`kinora-remote` stays until kudo's context store moves over. Roots now sync
too, as append-only streams (kino://02be1c37832e1c710030e7bc5a89441b55bdbf5a05ebe2c501f824708b7f3372) — the escape hatch above, taken.
