# Plan — a store mirrored to an object store

**Task:** kino://c650f51df78e4018da6bb0ec59a22aa08d52708167f3490e3194f9cd67d2383c

## Phase 1 — push and pull, offline

A `kinora-remote` crate (async, `object_store`; the core crate stays sync and
dependency-light). `push` and `pull` over the `store/` and `staged/` trees,
put-if-absent on push, hash check on pull, temporary files skipped. Tested
against `object_store`'s in-memory and local-filesystem backends: two stores
meeting through one mirror end with the union of their files.

Status: done (21 Oct). A fresh review found staged events unchecked, kinora's
`.jsonl.tmp` files synced, events before blobs, a shared pull temporary, a
billed LIST on every push; all fixed (spec v2): events verified as canonical
lines, a whitelist of kinora's own names, blobs first, a remembered push with
`push_all` for a mirror that lost files.

## Phase 2 — an S3 mirror from the environment

`s3://bucket/prefix` plus endpoint and keys from the environment (the
`AWS_*` names, so any S3 tool's configuration carries over). A blocking
wrapper for sync callers. `kinora push` / `kinora pull`. A live round trip
against Cloudflare R2 once the bucket exists.

Status: in progress (21 Oct). Built: `Mirror::from_url` (`s3://`, `file://`,
`memory://`), `from_url_with` for explicit S3 options, and a blocking face that
runs on a thread and runtime of its own (safe inside kudo's tokio runtime).
put-if-absent maps to `If-None-Match: *`, which R2 honours by default. Left:
the live R2 round trip (waiting on the bucket and token); the CLI's
`push`/`pull` deferred until something needs them.
