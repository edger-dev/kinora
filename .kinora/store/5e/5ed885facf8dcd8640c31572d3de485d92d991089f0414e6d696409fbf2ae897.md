# Spec — root versions and large kinographs keep their entries in moco's tree

**Contract.** A root version's entries — and a kinograph's, once it is
large — live in moco's content-defined sorted map (`moco:0c5355818d4ad254ff4e0184c89ecb486e2968dd59fc653f0324d2ab4920fa35`), keyed by kino id, each
entry's metadata inline. The root version (still a stream entry, kino://02be1c37832e1c710030e7bc5a89441b55bdbf5a05ebe2c501f824708b7f3372) holds its
header and the map's root hash. Every root uses the format; a small root is
one leaf chunk. A commit rewrites only the chunks its changes touch; a fold
diffs the heads against their base by subtree hash. A one-time migration
rewrites each root's latest version in the new format; older flat versions
still read.

**Why.** Kura roots hold 100k+ entries; a flat version rewritten per commit
does not scale, and one format for every root avoids two read, fold and
test paths.

**Rejected.** The tree only for large roots (two formats). Many small roots
per kura archive (every query and policy fans out).

**Escape hatch.** A root may stay flat while its readers lag; the reader
takes both formats.
